# Harness Agent 运行机制设计

状态：设计提案，2026-10-15。本文定义公共框架边界和实施约束，尚未实现新增运行机制。[English](../../en/architecture/agent-runtime.md)

目标是让宿主通过明确的定义、工具和触发器运行 Agent，并支持可靠接收、后台执行、进度观察和故障恢复。框架负责执行机制；使用框架的应用负责业务目标、授权规则、完成条件和结果。

## 1 范围与信息边界

公共仓库只保存可独立使用的运行契约、基础设施适配和通用 UI 组件。非公开的业务规则、产品方案、提示词、数据、内部记录和实施进度由其授权的私有位置维护。名称替换不能代替信息来源审查。

Agent 是一组指令、上下文构建方法和可调用工具的定义。Worker 是承载执行的进程。同一种定义可以在共享 Worker 中处理多个独立调用，无需为每个 Agent 创建进程。

Chat 是可选的输入与观察界面。无聊天界面的后台任务也能使用运行机制。已有固定步骤任务可以继续使用确定性处理器，只有需要模型选择下一步时才使用工具循环。

首期复用现有模型适配、模块注册、数据库、队列及领域服务，不建立新的通用流程平台。

## 2 责任划分

| 层 | 负责 | 不承担 |
| --- | --- | --- |
| Agent 定义 | 指令、上下文、工具集合、输入输出约束、运行预算 | 决定用户或系统的真实权限 |
| 触发适配器 | 验证来源、确定执行对象、去重、决定是否产生调用 | 在 Webhook 内等待模型执行 |
| 执行协调层 | 认领、租约、持久步骤、暂停、恢复、预算及状态 | 保存另一套业务结果或业务完成状态 |
| 工具执行层 | 参数校验、权限和版本检查、调用业务命令 | 用模型文字代替已完成的操作 |
| 业务服务 | 数据一致性、操作身份、真实结果、业务规则 | 依赖聊天连接维持执行 |
| 观察界面 | 经权限过滤的进度、消息、结果及控制入口 | 自行推断发送成功、结果版本或运行终态 |

模型不能任意指定 scope、执行身份、收件范围或工具集合。这些由宿主在经过授权的上下文中绑定。对敏感资源的每次访问与修改继续检查当前权限。

## 3 契约优先于数据表

先定义以下契约，再根据宿主已有数据结构选择存储方式。契约名称不意味着必须新增同名表。

| 契约 | 内容 |
| --- | --- |
| `AgentDefinition` | key、version、输入输出 schema、instructions、buildContext、tools、所需模型能力与预算 |
| `TriggerBinding` | 来源类型、验证方式、幂等身份、执行对象解析、输入影响策略 |
| `ExecutionTarget` | scope、actorRef、可选 subjectRef、服务端确定的 serialKey、控制版本 |
| `Run` | 一次被接收的逻辑调用、输入引用、定义版本、执行状态、已确认输出、累计预算 |
| `Attempt` | 该调用的一次执行尝试、epoch、leaseUntil、步骤、错误及恢复来源 |
| `ToolOperation` | 工具请求、稳定操作身份、业务结果引用、执行或核对状态 |
| `ResultRef` | 由业务服务解释的类型、ID 和修订号 |

持续工作可使用宿主已有的会话、任务或其他领域对象承载。框架不要求每个应用建立独立 `AgentWork` 表，也不把领域状态复制到运行表。一次请求没有持续业务对象时，只需要 Run。

同一 Run 的恢复保留原输入与操作身份，并追加 Attempt。一次新的用户要求或业务触发创建新的 Run。宿主若合并多个输入，需要显式记录其输入集合及处理结果。

业务目标完成与 Run 执行成功分别判断。例如成功返回一个问题表示本次调用完成，不表示整个业务目标完成。正常等待、需要人判断和业务异常由领域投影表达，不预先规定为同一个通用状态机。

### 3.1 最小持久性要求

宿主必须持久化接收凭据、Run、Attempt 或等价的追加事件、工具操作结果和未来唤醒依据。已有表能够满足这些约束时直接适配：

- 来源和消费者组成接收去重键；相同键但不同内容返回冲突。
- 一个服务端 serialKey 同时只有一个有效认领；该约束由数据库保证。
- Attempt 的 epoch 单调增加，旧认领不能覆盖新结果。
- 业务效果与其操作结果在同一事务中落地，或有可查询的持久操作账本。
- 未接收、已接收、已处理、被取代、忽略和等待依赖的输入有明确处置记录。
- 事件游标只跨过已处置的连续前缀，不越过未完成输入。

短事务通过显式 transaction context 传给相关存储方法。中立接口不引用 Prisma；宿主必须确保参与同一事务的方法确实使用同一个事务连接。

## 4 运行和恢复

```text
验证触发来源
      ↓
事务保存输入和调用身份
      ↓
队列通知 / 数据库恢复扫描
      ↓
认领 Attempt → 构建上下文 → 调用模型
                         ↑        ↓
                         └── 工具结果
                                  ↓
                  持久保存结果、消息和运行终态
                                  ↓
                    界面观察 / 后续业务触发
```

Run 状态为 `QUEUED / RUNNING / SUSPENDED / SUCCEEDED / FAILED / CANCELLED`。`SUSPENDED` 仅用于等待当前调用的异步工具或执行依赖；恢复后沿用本次调用的累计预算。等待用户以后提出新要求，或等待未来业务事件，由宿主保存条件并结束当前 Run。

1. 入口校验用户、范围、输入及幂等键，在短事务中保存输入引用和接收记录；存在消息时同时保存消息及附件关系。
2. 提交后尝试入队，返回接收标识。通知失败不撤销已接收事实，由扫描补发。
3. Worker 条件认领并建立 Attempt，记录 epoch、租约和输入范围。模型执行期间不持有数据库事务锁。
4. 加载固定版本的定义、当前权限和业务事实、有效历史及输入。记录必要的来源引用，而非默认复制所有原始内容。
5. 持久化工具请求，通过工具边界执行。保存真实结果后再进入下一模型步骤。
6. 保存输出或明确的暂停依赖，完成本次 Attempt。正式消息、可见结果引用和 Run 状态的更新有明确事务或恢复责任。
7. 新输入保持独立的接收与处理状态，不能因当前 Run 完成而被一并标记处理。

租约失效、取消或失去权限后，旧 Attempt 的结果不得提交。恢复首先读取持久工具结果和外部操作状态；不能从头盲目重放所有工具。诊断记录写入失败也不能让已经成功的业务命令失去其操作身份。

## 5 新输入与控制操作

每条新输入不一定使当前运行过期。触发适配器按业务含义声明影响：

| 策略 | 行为 |
| --- | --- |
| `observe` | 记录事实，不触发模型执行 |
| `append` | 接收后排队，当前执行可以继续 |
| `supersede` | 使受影响的未提交计划失效，后续从新输入和现有结果继续 |
| `control` | 暂停、取消、接管或撤销授权，立即提高控制版本 |

输入序号只表示处理进度。控制版本表示是否仍允许执行。业务资源修订号表示某次读写是否冲突。三者分别检查，避免正常消息流不断打断执行，也避免旧业务计划覆盖新状态。

控制命令与认领检查在数据库中串行化。关闭页面只断开观察连接；停止执行需要独立命令。暂停后保留新输入，恢复时由业务策略决定继续、重算或忽略哪些过时输入。

外发动作认领进入 `dispatching` 后可能已跨越外部服务边界。暂停可以阻止新的认领，并要求未外发执行器再次检查状态；已经在途的请求不能承诺撤回。界面需要保留这一实际状态。

## 6 工具和副作用

工具提供版本、说明、输入与输出 schema、效果类别、权限需求和执行函数。默认顺序执行写操作；只有明确独立的读取才允许并发。

读取工具返回受限数据及来源引用。内部修改工具调用业务服务，检查预期修订号。外部效果工具先保存操作意图，再通过现有邮件、存储等适配层执行。

框架要求有副作用的工具提供幂等与恢复契约，但不从模型文本猜测操作身份。业务服务决定什么是同一意图、什么是新的操作，以及同一身份下参数变化应被替换还是拒绝。不能仅用临时 toolCallId 或正文哈希防重。

外部操作有独立的认领、租约和状态。创建意图时检查 Run 权限；实际执行时再次检查当前授权与业务前置条件。原 Run 正常结束不自动取消已接收的操作。

| 操作结果 | 运行器处理 |
| --- | --- |
| 已确认成功 | 使用持久结果；不重新执行 |
| 已确认未执行的暂时失败 | 在累计预算内重试 |
| 已接收但尚未完成 | 保存等待依赖，释放 Worker，结果事件到来后恢复 |
| 执行结果未知 | 查询原操作，无法确认时保留异常；禁止盲目重发 |
| 业务冲突 | 返回最新事实，由授权内的新决策处理 |

框架提供可恢复执行，不承诺跨外部系统严格 exactly once。真实业务记录和外部回执决定结果；`pending` 不能显示成已完成。

需要人批准的动作由业务规则声明，并绑定实际参数、适用范围、版本和有效期。已有权限内的普通操作无需增加通用审批。撤销和补偿遵守具体业务能力，不以删除记录模拟撤销效果。

## 7 事件和未来唤醒

现有 `appEvents` 是进程内通知，处理失败被隔离记录。其返回不能证明事件已被可靠消费。

源业务事务应保存可靠投递依据；消费者以来源 ID 和 consumerKey 幂等接收后确认。`appEvents.emit()` 和队列用于加速，数据库中的未完成投递负责恢复。已有可靠 outbox 可直接复用，不要求再并行维护另一份。

未来唤醒保存明确时间、时区、原因、有效条件和计划版本。最近唤醒可由宿主已有任务记录承担；有独立生命周期的多个计时器再使用明细表。到期事件带稳定去重键，过时计划只记录忽略原因。

恢复扫描覆盖未通知的已接收调用、过期租约、到期唤醒和待核对操作。它不自行重做业务决策。停机恢复后是否追赶、合并或跳过过时事件，由业务策略决定。终态调用不会被任意迟到事件重新打开。

## 8 模型与上下文

保留现有 AI SDK 和供应商适配。公共运行契约只规范所需输入、工具调用、完成原因和用量，不复制一套完整的供应商 API 或另建重复的模型循环。适配器必须能把工具提交交给持久执行边界。

模型就绪检查针对实际选择的连接、模型及所需能力；工具依赖单独检查。版本和能力不兼容时给出明确阻塞，不静默切换行为。已开始的调用记录定义版本；恢复只能使用兼容实现或经过显式迁移。

上下文优先包含当前权威业务状态及本次输入，历史辅助解释。用户消息只加入一次；分支聊天按有效祖先链选取历史。摘要可重建，原材料由其存储所有者管理。

附件有访问范围、原消息关联和处理状态。不支持的格式应明确反馈。材料、引用文本和工具结果不能改变工具权限或系统规则。不同受众使用独立上下文投影，不能因为共享会话组件而合并私有内容。

## 9 可选协作界面

统一交互契约包括：可靠接收、真实进度、结果引用、明确的问题、停止当前执行、恢复及错误说明。布局、领域导航、状态名称和结果视图由应用组合，不强制所有业务使用一个固定工作台。

消息持久记录与执行日志分别存储。界面不从模型请求或 Run 输入拼装历史；执行日志也不默认对聊天参与者可见。结果面板通过业务服务读取实际版本。

只读订阅支持从游标恢复。一个流内使用单调序号，游标绑定 streamId 和权限范围；跨多个 Run 的聚合视图由宿主提供同样稳定的流身份。不能把不同 Run 内的序号直接混成全局游标。

快照与后续事件采用一致的高水位。客户端按事件 ID 和版本去重；游标过期时重新加载快照。文本增量可合并保存，但正式消息、工具结果及终态必须可恢复。草稿增量带 Attempt 标识，旧尝试的延迟数据不得覆盖新内容。

订阅开始及持续发送时检查权限变更。关闭观察连接不取消执行。列表默认 20 条并使用游标分页。公共错误只返回稳定错误码和可操作说明。

## 10 配置与诊断

分别处理代码安装、允许新调用、模型连接就绪、工具依赖与执行授权。禁用新执行不能丢弃历史、已接收副作用的核对或费用结算。

模块未启用时不暴露执行入口。关闭或移除模块前必须明确谁继续负责受权历史读取、取消、入站回执和结算；这些可以由独立的基础能力承接。无法保留这些责任时，先排空或显式迁移存量工作。

每次调用有步数、时长、工具次数和费用预算，同一调用的所有 Attempt 共用累计限制。业务可另设范围级并发和用量限制。费用结算通过现有 billing service，并具有独立幂等身份和恢复记录。

诊断默认记录关联 ID、定义与模型版本、时长、用量、状态及错误码。完整提示词、材料、响应和工具正文按数据策略选择是否采集；需要明确访问权限、保留期限、加密和删除责任。密钥与认证令牌不得进入日志，不能将供应商未提供的内部推理视为必需诊断。

可观察指标包括排队延迟、恢复时间、失败类别、重复动作拦截、未知副作用、费用和人工介入原因。业务成功指标由应用定义。

## 11 目录和实施顺序

| 归属 | 位置与约束 |
| --- | --- |
| 现有执行能力 | 复用 `packages/ai-chat` 及显式供应商适配，保持当前兼容入口 |
| 宿主运行绑定 | `src/server/agents` 中接入数据库、权限、预算和已有业务服务 |
| Worker 组合 | `src/workers/features` 注册 contribution，queues/processors 从现有索引导出；使用 `createWorkerInstance()` |
| 进程入口 | `services/worker`，不放业务策略，不依赖 Next 专用 API |
| 客户端协议 | 稳定后进入 `packages/contracts` 和 `packages/api-client`，不包含供应商协议与服务端依赖 |
| 中立运行包 | 两个独立、可公开的框架用例验证后再提取；不先规定必须新建一个包 |

先收敛现有聊天接收、权限、事务、附件和历史行为，再把模型执行从 HTTP 观察连接迁到 Worker。随后补齐接收去重、Attempt 恢复、工具账本和订阅；用独立构造的无外部副作用用例验证触发与唤醒边界，再考虑包提取。

每个执行对象只允许一个新旧执行器负责。迁移保留消息 ID、操作身份和结果版本，先停止旧认领再切换。历史回填不能触发工具。回滚要先核对在途操作，不能把新运行器已产生的效果重新交给旧运行器重放。

## 12 验收条件

以下描述应验证的行为，不表示已经执行验证：

- 重复提交和重复队列投递返回同一接收身份，不重复产生效果。
- 关闭页面不影响已接收调用；停止命令使旧 Attempt 无法提交。
- 持续追加输入不会让当前调用永久饥饿；控制操作能使受影响计划失效。
- 效果已提交而进程退出时，恢复依据原结果继续，不重复执行。
- 异步工具等待释放 Worker，并沿用本次调用预算恢复。
- 未知外部效果被核对；暂停如实显示已经在途的操作。
- 事件快照和恢复游标不丢失终态、不混入其他权限范围。
- 定义版本不兼容、模块停用和预算耗尽有明确处理责任。
- 公共改动可由仓库资料和独立示例解释，不携带非公开信息。
