# 添加能力

注册机制与源码布局分开处理。修改认证、数据库、支付、存储、队列或安全边界前，阅读对应集成文档。

- 框架代码保持通用。私有业务代码和文档留在私有产品仓库。
- 界面放在 `src/components`，客户端 Hook 放在 `src/hooks`，服务放在 `src/server`，路由放在已有 API 目录，队列和处理器放在 `src/workers`。
- 优先复用已有职责归属，只创建实际需要的文件，不要求每项能力套目录模板或拆成包。
- 只有实际消费者需要独立依赖边界时，才提取共享包。
- 可选能力继续通过 `FrameworkModule` 和 `src/config/modules.ts` 注册、启停。关闭后拒绝新执行，同时保留已指定责任方负责的历史、取消、回执和结算。
- 校验输入，从可信认证中取得身份，在服务中检查所有权。
- 业务输入和执行记录在同一个事务中接受。队列投递是可恢复通知，数据库才是接受凭据。
- 路由保持轻薄，Worker 保持幂等，使用已有数据库、存储、计费和事件抽象。
- 持久化改动附带可部署的 Prisma migration。

完成后遵循[完成清单](./completion-checklist.md)，同时尊重用户明确指定的验证范围；用户保留集成验证时，不主动添加或运行自动化测试。
