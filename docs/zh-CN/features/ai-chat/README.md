# AI Chat

**语言：** [English](../../../en/features/ai-chat/README.md) | 简体中文

Chat 是 Worker 执行的输入和观察界面。HTTP 请求只接受执行，不拥有模型和工具的生命周期。

```text
ChatPanel → POST /api/chat → 同一事务：输入、回复占位、AgentRun
                                      ↓ 通知及恢复扫描
                            Worker → Agent 执行器 → 模型和已注册工具
                                      ↓ 持久化消息快照
ChatPanel ← GET /api/chat/:id/run ← 有权限的会话投影
```

## 职责

界面和交互分别在 `src/components/ai-chat`、`src/hooks/ai-chat`；会话接受、投影和执行器在 `src/server/ai-chat`；通用执行、租约、尝试和工具操作记录在 `src/server/agents`；队列入口在 `src/workers`。

保留 `src/config/modules.ts` 和 `src/server/modules` 的注册启停机制。不新增运行时包，也不要求一项能力对应一个包。继续使用现有模型适配器。

## 运行与恢复

配置 `OPENROUTER_API_KEY`，启用已安装的 AI Chat，同时启动使用同一 PostgreSQL、Redis 的 Web 和 Worker。启动前应用新增的执行记录 migration。当前宿主使用 OpenRouter，其他模型供应商的密钥不能代替该配置。

- 输入、回复占位和 Run 在同一事务保存。同一个请求 ID 和内容重复提交会返回原 Run，内容不同则拒绝。
- 同一会话串行执行。数据库唯一约束、epoch 和 60 秒租约限制有效执行者；每 15 秒恢复扫描，过期尝试最多重试三次。
- 每个 Run 累计最多 12 个模型步骤，每步最多输出 4,096 tokens；单次尝试最多 15 分钟，Run 24 小时后过期。依赖等待释放 Worker，不消耗失败重试额度。
- 页面轮询持久化消息快照，关闭页面不会取消任务。取消通过显式权限校验的请求完成，已完成的外部操作不会回滚。
- 历史按父链选择。编辑建立分支，执行过工具的回复拒绝重新生成。当前执行和观察窗口最多读取 1,000 条交互，祖先不完整时明确拒绝。
- 工具操作保存稳定身份、输入和结果。只读、明确支持幂等的操作可以恢复；结果不明的副作用停止为 `TOOL_OUTCOME_UNKNOWN`，在宿主核对前阻止自动重试及该会话的新输入。
- 图片工具复用幂等任务，短暂查询后进入等待。文档写入目前采用保守的不重放策略，业务写入和执行记录尚非一个原子事务。
- 接受输入、取得执行权、模型步骤、工具调用、保存快照和续租均校验权限。能力关闭后已接受执行暂停，历史和取消仍可用。
- 游客所有权由 HTTP-only cookie 及数据库中的哈希验证，不信任客户端自造 ID。游客不能调用工具或上传文件；旧的无所有权哈希游客会话不会被自动认领。
- 附件目前仅支持当前账号上传的图片，校验存储 URL 所有权，不支持的格式明确拒绝。
- 已记录 token 用量按 Run ID 幂等结算；崩溃或取消造成的缺失用量标记为不确定，不虚构供应商账单或自动估算收费。

## 范围

本轮落地通用执行路径和 Chat 适配器，不包含私有业务流程、独立业务任务系统、公开的定时或 Webhook 创建 API、审批界面、未知副作用自动核对或跨端客户端。其他触发方式应在自己的权限边界和业务事务中使用相同接受与执行接口。

会话和必需的工具输入输出是应用数据；不把原始供应商响应或推理轨迹作为诊断日志保存。私有提示词、业务规则和流程实现留在私有产品仓库。
